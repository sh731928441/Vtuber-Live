# Disco产品需求文档

## 一、产品概述

### 1.1 产品定义

Disco是一款基于直播平台的**弹幕驱动型实时互动云蹦迪产品**。用户通过发送弹幕即可在虚拟夜店场景中创建属于自己的 大肥鱼 形象，通过文字指令操控角色移动、装扮、表达情绪，付费用户可登上 DJ 台掌控全场节奏，实现万人同场的线上社交蹦迪体验。

### 1.2 产品定位

- **品类**：直播互动游戏 / 虚拟社交娱乐
- **核心价值**：低门槛参与感、强社交氛围、情绪释放出口
- **slogan**：发送弹幕，即刻化身修勾加入万人蹦迪

### 1.3 参考原型

对标 B 站 "修勾夜店老板" 直播间形态，该产品巅峰同时在线 60 万人，日均占据 B 站直播人气榜首位，验证了弹幕互动 + 虚拟蹦迪模式的市场可行性扬子晚报。

## 二、市场背景与需求分析

### 2.1 市场背景

2. **线上娱乐需求爆发**：年轻人夜间娱乐需求多元化，线下夜店门槛高、成本高，云蹦迪提供低成本替代方案
3. **弹幕互动直播兴起**：弹幕从单纯评论功能进化为游戏输入信号，衍生出大量互动玩法
4. **虚拟社交接受度提升**：Z 世代偏好匿名化、形象化的线上社交

### 2.2 用户核心需求

| 需求层级 | 具体需求                 | 满足方式                |
| -------- | ------------------------ | ----------------------- |
| 基础参与 | 低成本加入蹦迪，无需下载 | 发送弹幕即创建角色      |
| 社交互动 | 与他人同场互动           | 弹幕气泡  + 全场喊话    |
| 成就感   | 脱颖而出，掌控全场       | DJ 特权系统 + 特写镜头  |
| 情绪释放 | 解压、狂欢、氛围感       | 灯光音乐 + 万人同场氛围 |

### 2.3 目标用户画像

- **核心用户**：18-28 岁 Z 世代，学生 / 年轻职场人，夜间活跃
- **次要用户**：喜欢电音、蹦迪文化的爱好者
- **付费用户**：有展示欲、愿意为特权和存在感付费的用户
- **用户特征**：熟悉弹幕文化、热衷网络梗、社交需求强、消费力中等

## 三、核心玩法设计

### 3.1 基础参与流程

2. **进入直播间**：用户无需任何操作即可观看
4. **创建角色**：发送 "创建角色" 或任意弹幕，系统在舞池随机位置生成一只绑定用户 ID 的 大肥鱼
6. **角色操控**：通过发送指定指令弹幕控制角色行为
8. **沉浸体验**：跟随音乐节奏，角色自动摇摆，配合灯光特效营造蹦迪氛围
10. **进阶互动**：通过打赏获得 DJ 特权、特写镜头等高级玩法

### 3.2 指令系统设计

#### 3.2.1 基础免费指令

**移动类指令**

- `移动` / `移动到XX方向`：角色向指定方向移动一段距离
- `停下`：角色停止移动，原地蹦迪
- `跳`：角色做出跳跃动作

**装扮类指令**（持续一段时间后自动消失）

- `墨镜`：角色戴上墨镜
- `可乐`：角色手持可乐
- `奶茶`：角色手持奶茶
- `薯条`：角色手持薯条
- `玩手机`：角色做出低头玩手机动作

**表情类指令**（持续数秒）

- `大哭`：角色流泪大哭
- `大笑`：角色开心大笑
- `无语`：角色翻白眼
- `喜欢`：角色冒爱心
- `礼貌`：角色鞠躬
- `生气`：角色冒怒气
- `？`：角色头顶出现问号

**互动类指令**

- `骰子`：掷骰子，生成 1-6 随机数字显示在角色头顶

#### 3.2.2 付费特权指令

**DJ 特权**（礼物榜前三名轮值）

- `切歌`：切换下一首背景音乐
- `切镜头`：切换全场摄像机视角
- `一起喊+内容`：全场所有大肥鱼头顶同时显示指定文字
- `灯光`：切换灯光模式

**特写特权**（单笔礼物达到阈值）

- 摄像机给该用户的大肥鱼 3-5 秒特写镜头
- 角色周身出现金色光芒特效

### 3.3 核心游戏循环

```
进入直播间 → 发弹幕创建角色 → 指令操控互动 → 
寻找自己的大肥鱼 → 
（付费路径）打赏获得特权 → 成为DJ掌控全场 → 
持续参与 → 次日复访
```

## 四、功能模块详细设计

### 4.1 角色系统

#### 4.1.1 角色创建

- 触发条件：用户首次发送有效弹幕
- 角色形象：基础 大肥鱼 纸片人形象，支持左右朝向(水平翻转即可)
- 角色命名：头顶显示用户 ID（超长自动截断）
- 生成位置：舞池区域内随机坐标
- 角色上限：单场支持 10000 + 个角色同时显示（超出做层级优化）

#### 4.1.2 角色状态管理

- 在线状态：用户活跃期内角色持续存在
- 离线机制：用户超过 5 分钟无新弹幕，角色逐渐淡出消失
- 重进机制：用户再次发弹幕，在新位置重新生成
- 对象池：使用对象池技术复用角色资源，避免频繁创建销毁

### 4.2 场景系统

#### 4.2.1 场景分区

- **DJ 台区域**：场景正前方高台，当前 DJ 的放大形象站立于此
- **主舞池**：核心区域，大部分用户角色聚集区
- **边缘区域**：舞池四周，角色密度较低
- **背景大屏**：播放 MV 或视觉特效
- **两侧装饰**：烧烤摊、吧台等趣味元素

#### 4.2.2 灯光特效系统

- 主灯：跟随音乐节拍闪烁
- 激光束：周期性扫射效果
- 频闪灯：高潮段落触发
- 霓虹氛围灯：场景整体色调
- 烟花特效：大额礼物触发全场烟花

#### 4.2.3 摄像机系统

- 默认视角：固定全景视角
- 自动巡游：周期性缓慢推拉摇移
- DJ 切镜：DJ 可触发视角切换
- 特写镜头：付费用户专属特写
- 随机聚焦：随机选取区域放大

### 4.3 弹幕解析系统

#### 4.3.1 指令识别规则

- 精确匹配：指令词完全匹配时触发对应动作
- 模糊匹配：包含关键词即触发（如 "移动到左边" 识别为移动指令）
- 非指令弹幕：以对话气泡形式显示在角色头顶
- 优先级：DJ 指令 > 付费用户指令 > 普通用户指令

#### 4.3.2 指令冷却与限流

- 单用户指令间隔：最低 2 秒冷却
- 单场指令处理上限：每秒处理 2000 条指令
- 溢出策略：超出部分仅显示弹幕气泡，不执行动作
- 防刷屏：相同指令短时间重复发送只执行一次

### 4.4 DJ 系统

#### 4.4.1 DJ 选拔机制

- 实时礼物榜前三名自动成为轮值 DJ
- 每位 DJ 任期 5 分钟，到期自动轮换
- 同分规则：先达到者优先
- 下播重置：每场直播独立计算

#### 4.4.2 DJ 权限

2. 角色放大并站在 DJ 台上
4. 可执行切歌指令（歌单范围内）
6. 可切换灯光模式
8. 可发起 "一起喊" 全场弹幕
10. 可切换摄像机视角
12. 专属 DJ 标识与金色光效

#### 4.4.3 歌单系统

- 预设歌单：电音、EDM、热门舞曲分类
- DJ 点歌：DJ 可从备选歌单中选歌
- 节奏检测：音乐节拍自动同步灯光和角色动作频率

### 4.5 礼物与经济系统

#### 4.5.1 礼物档位设计

| 礼物档位 | 价值（元） | 对应效果                             |
| -------- | ---------- | ------------------------------------ |
| 小额礼物 | 0.1-1      | 角色短暂发光，增加贡献值             |
| 中额礼物 | 10-50      | 30 秒金色特效，贡献值大幅增加        |
| 大额礼物 | 100+       | 5 秒特写镜头 + 全场特效 + 巨额贡献值 |
| 超级礼物 | 500+       | 10 秒特写 + 全场烟花 + 直接冲榜      |

#### 4.5.2 贡献值系统

- 发送弹幕获得少量贡献值
- 赠送礼物按比例获得贡献值
- 贡献值决定礼物榜排名
- 每日 / 每场独立计算

### 4.6 社交互动系统

#### 4.6.1 弹幕气泡

- 非指令类弹幕以白色气泡形式显示在角色头顶
- 气泡停留 3-5 秒后消失
- 支持表情符号显示
- 同屏气泡过多时自动分层显示

#### 4.6.2 全场喊话

- DJ 发起 "一起喊 + 文字" 指令
- 全场所有大肥鱼顶同时显示该文字
- 持续 5 秒后消失
- 有冷却时间限制（每 30 秒一次）

## 五、技术架构方案

### 5.1 整体技术架构

```
┌─────────────────────────────────────────┐
│              直播平台层                  │
│  (B站/抖音/视频号 直播推流与弹幕)        │
└─────────────┬───────────────────────────┘
              │ 弹幕/礼物数据流
┌─────────────▼───────────────────────────┐
│           弹幕采集与解析层               │
│  (WebSocket连接 + 指令识别 + 过滤)       │
└─────────────┬───────────────────────────┘
              │ 标准化事件
┌─────────────▼───────────────────────────┐
│           游戏逻辑层                     │
│  (Unity引擎 + 角色管理 + 场景管理)       │
│  (DJ系统 + 礼物特效 + 灯光音乐)          │
└─────────────┬───────────────────────────┘
              │ 渲染画面
┌─────────────▼───────────────────────────┐
│           推流输出层                     │
│  (OBS/FFmpeg 编码推流到直播平台)         │
└─────────────────────────────────────────┘
```

### 5.2 核心技术选型

#### 5.2.1 游戏引擎

- **引擎**：Unity 2022 LTS
- **渲染管线**：URP 通用渲染管线（性能与画质平衡）
- **开发语言**：C#
- **部署方式**：PC 端运行，画面采集推流

#### 5.2.2 弹幕采集方案

**方案 A：平台官方 API**（推荐）

- 接入对应平台开放平台的直播弹幕 WebSocket 接口
- 优点：稳定合规，数据准确
- 缺点：需要申请权限，不同平台接口不同

**方案 B：第三方弹幕库**

- 基于开源项目（如 B 站弹幕姬、抖音直播弹幕采集）
- 优点：开发快，无需审核
- 缺点：稳定性差，有合规风险

#### 5.2.3 性能优化方案

**万人同场优化策略**：

2. **角色合批**：使用 GPU Instancing 批量渲染相同角色
4. **LOD 分级**：远处角色降低精度，只保留剪影
6. **分层显示**：超出显示上限时，优先显示付费用户和近期活跃用户
8. **对象池**：角色对象复用，避免 GC
10. **帧率控制**：目标 30fps，降低渲染压力
12. **弹幕限流**：每秒处理指令数设置上限

### 5.3 关键模块技术实现

#### 5.3.1 弹幕解析模块

```
输入：原始弹幕数据（用户ID、用户名、内容、时间戳）
处理流程：
  1. 敏感词过滤
  2. 指令词匹配（正则匹配指令库）
  3. 用户身份识别（普通/DJ/付费）
  4. 指令权限校验
  5. 冷却时间检查
  6. 分发到对应游戏逻辑
输出：标准化游戏事件
```

#### 5.3.2 角色管理模块

- 数据结构：Dictionary <用户 ID, 角色对象>
- 空间管理：网格划分，快速查找附近角色
- 生命周期管理：活跃计时器，超时自动回收
- 状态机：待机 / 移动 / 蹦迪 / 表情 / 特效等状态

#### 5.3.3 音乐节拍检测

- 方案 A：预标记节拍点（精确，工作量大）
- 方案 B：实时音频分析（使用 Unity 音频频谱分析）
- 节拍事件驱动灯光闪烁、角色动作频率

### 5.4 服务器需求

- **单机运行**：初期单台高性能 PC 即可支撑

  - CPU：AMD 5800X 及以上
  - 显卡：RTX 5060 及以上
  - 内存：32GB 以上
  - 网络：上行带宽 10Mbps 以上

- **分布式扩展**：后期可拆分为采集服务 + 游戏渲染服务

## 六、UI 与视觉设计规范

### 6.1 整体视觉风格

- **主色调**：深紫 + 霓虹粉 + 电光蓝，典型夜店霓虹风格
- **氛围**：昏暗环境 + 点状光源 + 烟雾效果
- **美术风格**：低多边形 + 纸片人，卡通搞笑风
- **视觉重心**：DJ 台 + 主舞池区域

### 6.2 角色设计规范

- **基础形象**：大肥鱼纸片人
- **尺寸**：基础高度约占画面高度 1/30
- **动画**：上下浮动 + 左右摇摆的循环蹦迪动画
- **朝向**：移动时角色朝向移动方向
- **装扮叠加**：装扮物品以 Sprite 形式叠加在对应位置

### 6.3 界面元素布局

```
┌─────────────────────────────────────────────┐
│  顶部：当前歌曲信息 + 在线人数 + DJ信息      │
├─────────────────────────────────────────────┤
│                                             │
│                主游戏画面                   │
│           （舞池+DJ台+灯光特效）            │
│                                             │
├─────────────────────────────────────────────┤
│  左侧：礼物榜TOP5                           │
│  右侧：指令说明 + 快捷礼物按钮               │
│  底部：当前DJ剩余时间 + 下一位预告          │
└─────────────────────────────────────────────┘
```

### 6.4 特效设计

- **入场特效**：角色生成时淡入 + 小弹跳
- **装扮触发**：物品出现时缩放动画
- **表情触发**：表情图标弹出 + 飘动
- **礼物特效**：从屏幕上方掉落 + 闪光
- **DJ 上台**：聚光灯 + 上升动画
- **全场喊话**：文字波浪式扩散出现

## 七、运营与商业化策略

### 7.1 运营节奏

#### 7.1.1 开播策略

- **固定时段**：每晚 21:00-24:00 开播，培养用户习惯
- **时长**：3-4 小时 / 天
- **预告机制**：开播前 1 小时发布动态预告
- **节假日专场**：情人节、万圣节、跨年等主题专场

#### 7.1.2 内容运营

- **主题夜**：每周设定不同主题（如复古迪斯科夜、二次元专场）
- **联动活动**：与游戏 / 品牌合作定制皮肤和场景
- **用户投稿**：征集用户点歌、创意指令
- **社群运营**：建立粉丝群，收集反馈，预告活动

### 7.2 商业化模式

#### 7.2.1 直播打赏分成（核心收入）

- 平台礼物分成（约 50% 分成比例）
- 核心付费点：冲榜当 DJ、特写镜头、特效展示
- 参考数据：原修勾夜店单月礼物收入约 13-15 万元

#### 7.2.2 品牌合作收入

- 品牌定制专场：更换场景皮肤、植入品牌元素
- 定制角色装扮：品牌联名装扮
- 大屏广告：背景大屏播放品牌 MV / 广告
- 参考报价：植入视频 1.9 万，定制视频 2.4 万

### 7.3 用户增长策略

2. **内容裂变**：用户截图 / 录屏分享社交平台
4. **梗文化传播**：依托 大肥鱼 表情包的天然传播属性
6. **KOL 联动**：邀请 UP 主 / 主播连麦体验
8. **平台推荐**：争取直播广场推荐位
10. **SEO 优化**：关键词覆盖 "云蹦迪"" 大肥鱼夜店 ""线上蹦迪"

## 九、风险评估与应对
