# 云蹦迪直播间 Web 端开发文档

**版本**：v0.1  
**技术栈**：PixiJS v8 + pixi-viewport v6 + WebSocket  
**目标**：实现类似 B 站“修勾夜店”的 2D 横版云蹦迪直播间，支持背景图 + 舞台、顶部柔光散射、自由移动镜头、弹幕观众实时互动。

---

## 1. 项目概述

### 1.1 产品目标

在浏览器中构建一个可直播推流的 2D 横版夜店场景。观众通过发送弹幕/礼物进入场景，生成对应的蹦迪角色；主播/运营可通过自由镜头观察全场。视觉重点为**舞台背景**、**顶部柔光散射光效**和**流畅的镜头操控**。

### 1.2 核心需求

| 编号 | 需求                                                   | 优先级 |
| ---- | ------------------------------------------------------ | ------ |
| R1   | 加载背景图片与舞台层，支持 2D 横版世界                 | P0     |
| R2   | 支持创建角色纸片人，可左右移动，左右朝向使用水平翻转   | P0     |
| R3   | 顶部柔光散射光效，非直线光束，带呼吸/漂移动画          | P0     |
| R4   | 自由镜头：拖拽平移、滚轮/双指缩放、惯性减速、边界限制  | P0     |
| R5   | 通过 Vtuber-Live 接收弹幕/礼物事件，生成并驱动观众角色 | P0     |
| R6   | 角色蹦迪动画（跳动、摇摆、挤压拉伸）                   | P2     |
| R7   | 性能控制场景角色数量                                   | P1     |

### 1.3 非目标

- 不做 3D 场景与真实体积光（godrays）渲染，初期用 2D 光晕叠加模拟。

- 不做用户账号体系，观众身份由直播平台 弹幕用户名 映射。

- 不自行实现推流，推流由 OBS/直播伴侣捕获浏览器画面完成。

## 2. 技术选型

| 模块     | 选型                                                          | 理由                                             |
| -------- | ------------------------------------------------------------- | ------------------------------------------------ |
| 渲染引擎 | **PixiJS v8**                                                 | WebGL/WebGPU 2D 渲染，性能好，生态成熟           |
| 镜头控制 | **pixi-viewport v6**                                          | 原生 drag/pinch/wheel/decelerate/clamp，开箱即用 |
| 光效     | PixiJS `Graphics` 径向渐变 + `BlurFilter` + `blendMode='add'` | 无需 shader 即可实现柔和散射光，性能可控         |
| 实时通信 | Vtuber-Live弹幕接入                                           | 弹幕/礼物低延迟推送                              |
| 构建     | Vite                                                          | 快速开发与打包                                   |
| 语言     | TypeScript（建议）                                            | 类型安全，便于多人协作                           |

> 说明：B 站原版底层为 Unity，本方案用 Web 技术复刻其 2D 横版视觉与交互，不追求 1:1 引擎级一致。

- 世界背景图片选择

- 灯光参数

## 4. 模块设计

### 4.1 世界与镜头模块

**世界尺寸**：建议 `1920 × 1080`（可配置）。所有场景元素放入 `viewport`，镜头移动即世界移动。

**验收标准**：

- 鼠标拖拽可平滑的移动镜头，松手有惯性；

- 滚轮/双指可缩放，范围 0.5–2.5；

- 世界边缘不会被拖出屏幕；

- 窗口 resize 后 viewport 同步尺寸。

### 4.2 背景与舞台模块

- 背景图使用 `Sprite.from('bg.png')`，尺寸对齐世界尺寸，置于 `BackgroundLayer` 最底层。

- 舞台用 `Graphics` 圆角矩形 + 霓虹描边占位，后续替换为美术切图。

- 建议背景图导出为 **WebP**，分辨率不超过 4096×2048，避免显存过大。

### 4.3 柔光散射模块（核心视觉）

**原理**：径向渐变圆 + 高斯模糊 + 加色混合 + 缓慢漂移/呼吸。

**实现要点**：

1. 每个光源用 `Graphics.fillGradient({ type: 'radial', colorStops: [...] })` 画中心亮、边缘透明的圆。

2. 对光源容器添加 `BlurFilter({ strength: 18, quality: 3 })`，`strength` 控制柔化程度，建议 10–18。

3. 光源容器设置 `blendMode = 'add'`，叠加后变亮而非互相遮挡。

4. 在 Ticker 中驱动 `x/y` 正弦漂移与 `alpha` 呼吸。

**参数建议**：

| 参数          | 建议值             | 说明                   |
| ------------- | ------------------ | ---------------------- |
| 光源数量      | 5–8                | 过多会过曝且增加填充率 |
| 半径          | 140–240            | 根据舞台宽度调整       |
| Blur strength | 10–18              | 低端设备降至 8–10      |
| 基础 alpha    | 0.3–0.5            | 叠加后整体亮度需实测   |
| 漂移幅度      | x: 20–60, y: 10–30 | 避免光斑跳动感         |

**验收标准**：光斑边缘柔和无硬边，整体呈散射状，无直线光束感，动画帧率稳定。

### 4.4 观众角色模块

角色是单张PNG纸片人（大肥鱼风格）。每个角色只有一张默认朝向为左的贴图，朝向通过水平翻转实现，视觉上始终只有“原图/镜像图”两个朝向。角色支持多套纸片人皮肤，创建时随机分配，运行中可被弹幕指令切换。纸片人角色蹦迪动画（跳动、摇摆、挤压拉伸），移动动画（摇摆）



**性能上限**：同屏角色建议 ≤ 100；可在页面配置限制，超出则停止创建；弹幕活跃降低后销毁角色，默认十分钟内没发弹幕/送礼/点赞/关注则销毁角色。

### 4.5 网络与消息协议

接口地址：ws://127.0.0.1:8787/ws



**WebSocket 消息示例**：

```json
// 创建角色（开发时再完善）
{"kind":"disco","t":"01:01:48","type":"create", ...}

// 角色移动（开发时再完善）
{"kind":"disco","t":"01:02:39","type":"move","direction": "left", "value": "20", ...}

// 切换角色（开发时再完善）
{"kind":"disco","t":"01:15:44","type":"change", ...}

// 弹幕 角色说话气泡
{"kind": "event","t": "01:56:39","type": "danmaku","tname": "弹幕","desc": "Black_Kiven：好困呀","skip": null,  "test": false}

```

**前端处理**：

- 心跳 ping/pong 每 30s；

- 断线重连指数退避（1s/2s/4s/8s，上限 30s）；

- 消息限流：同一 uid 高频弹幕合并或丢弃，避免刷屏。弹幕字符长度超过50字符丢弃或过滤。

- Disco模式开启时，发送的所有弹幕不触发Vtuber-Live的弹幕回复，弹幕内容会在角色上方弹出白色气泡，并显示弹幕内容；

- 接受弹幕指令，`/disco ${指令名} ${指令值}`，示例：`/disco 创建角色` `/disco 移动 左 20` `/disco 切换角色`

### 4.6 UI 覆盖层

- 固定在 `app.stage`（不随 viewport 移动）的提示文字、调试 FPS、在线人数。

- 可隐藏调试信息，默认隐藏，在Vtuber-Live的Disco页面使用开关控制。

## 6. 性能优化

1. **分辨率上限**：`resolution = min(devicePixelRatio, 2)`，避免 4K 屏过度渲染。

2. **对象池**：角色、光效容器复用，减少创建销毁。

3. **离屏裁剪**：viewport 自带裁剪，但角色动画仍会计算；对屏幕外角色暂停 Ticker 更新。

4. **纹理压缩**：背景/舞台使用 WebP，避免超大 PNG。

5. **帧率监控**：`app.ticker.FPS` 低于 45 时自动降级光效与角色动画精度。（待定）

## 9. 风险与对策

| 风险              | 影响     | 对策                          |
| ----------------- | -------- | ----------------------------- |
| 柔光叠加过曝      | 视觉发白 | 降低 alpha、减少光源、调 Blur |
| 低端设备掉帧      | 直播卡顿 | 自动降级光效/角色数           |
| 弹幕洪峰          | 角色爆炸 | 服务端限流 + 前端合并         |
| 直播平台 API 变更 | 消息中断 | 适配层隔离协议                |
