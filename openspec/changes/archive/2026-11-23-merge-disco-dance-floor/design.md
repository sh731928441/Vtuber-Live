# Design

## Context

当前角色位置由 Python 端的 `mid`、`near` 双活动带约束，前端把角色放入两个固定容器，并分别计算缩放、亮度和层级。移动协议只有单轴方向与距离，因此即使扩大两个活动带的 Y 范围，也无法改变角色所属 `band`。相关行为见 `proposal.md` 和 `specs/disco-scene/spec.md`、`specs/disco-event-stream/spec.md`。

## Goals / Non-Goals

**Goals:**

- 用一条统一舞区矩形和连续纵深函数取代中景/近景归属。
- 兼容现有 `config.json`，自动迁移两个旧活动带。
- 支持任意顺序的左右、上下及双轴斜向指令。
- 保持现有角色、DJ 台、动态物品、柔光和性能边界。

**Non-Goals:**

- 不增加角色碰撞、寻路或自动避让。
- 不改变镜头运镜、角色上限、超时或弹幕处理。
- 不提供任意角度旋转或沿曲线移动。
- 不把斜向距离重新归一化为固定线速度。

## Decisions

### 1. 单一 `dance_floor` 配置

新配置结构为：

```text
disco.dance_floor
  x: [minX, maxX]
  y: [minY, maxY]
  scale: [backScale, frontScale]
  brightness: [backBrightness, frontBrightness]
```

默认使用旧双活动带范围的并集：`x=[140, 3700]`、`y=[620, 1040]`；缩放使用 `mid.scale[0]` 到 `near.scale[1]`，亮度使用 `mid.brightness` 到 `near.brightness`。旧 `z` 字段不再需要，角色层级由脚底 Y 直接决定。

相比保留两个带并在交界处插值，单一矩形更直接地表达“一个舞区”，也避免两套范围重叠、断层或交叉校验带来的歧义。

### 2. 在配置校验前迁移旧双活动带

加载原始配置时，如果旧配置没有 `dance_floor` 但存在有效的 `bands.mid` 和 `bands.near`，先计算：

```text
x = [min(mid.x[0], near.x[0]), max(mid.x[1], near.x[1])]
y = [min(mid.y[0], near.y[0]), max(mid.y[1], near.y[1])]
```

再生成 `dance_floor`，随后移除运行配置中的 `bands`。迁移必须发生在深合并默认值和 `validate_disco` 之前，否则默认 `dance_floor` 会掩盖旧配置的真实值。已有有效 `dance_floor` 优先，不根据旧字段覆盖。

迁移只改变配置形状，不重置活动角色坐标。现有配置保存使用临时文件加原子替换，迁移后的结构会随现有 `config.save` 持久化。

### 3. 服务端只保存 X/Y 与连续纵深

`DiscoCharacter` 移除 `band` 字段。创建角色时直接在舞区 X/Y 内随机取点；配置缩小后，对所有角色执行一次二维夹取；快照和增量消息不再要求 `band`。

舞区纵深进度定义为：

```text
p = clamp((y - y0) / (y1 - y0), 0, 1)
scale = lerp(backScale, frontScale, p)
brightness = lerp(backBrightness, frontBrightness, p)
zIndex = y
```

前端只保留一个角色容器，容器整体位于背景柔光之上、DJ 台之下。这样角色跨越旧分界时不会换父容器，也不会发生层级跳跃。

### 4. 移动指令解析为二维位移

新增移动解析器，从 `移动` 或 `移动到` 后提取一至两个方向及各自可选距离。方向与数字之间允许零到一个或多个空白，因此同时支持 `左20`、`左 20`、`上30`。

- `左` → `dx` 为负。
- `右` → `dx` 为正。
- `上` → `dy` 为负。
- `下` → `dy` 为正。
- 未填写距离时使用 `disco.move_step`。
- 两个轴的距离分别应用，不按斜线长度归一化。
- 同一轴重复、超过两个方向轴、零方向或残留无法识别文本时拒绝指令。

解析结果先合并成目标 `x/y`，再一次性夹取到舞区。若只有一个轴越界，另一个轴仍保留有效位移。仅当水平分量非零时更新朝向；纯上下移动保留原朝向。

### 5. 前端与控制台同步采用舞区字段

前端类型、默认配置、角色校验、几何计算和控制台输入全部改用 `dance_floor`。控制台保留现有 X/Y 范围编辑能力，并增加后侧/前侧缩放和亮度端点输入。角色名称继续跟随角色，统一使用清晰描边；亮度变化通过角色容器透明度实现。

## Risks / Trade-offs

- **旧配置迁移会立即改写 `config.json`** → 迁移前保留旧双带值到运行时计算中，使用现有原子保存，并在发布前备份用户配置验证迁移结果。
- **斜向移动每个轴都使用完整距离，实际位移比单轴更大** → 这是已确认的指令语义；控制台说明明确两个数字分别代表 X、Y。
- **单一容器内角色较多时排序成本与两个容器合计相同** → 继续按脚底 Y 设置子项层级，并沿用离屏角色节流，维持 100 人性能目标。
- **旧角色没有 `band` 后大小可能略有变化** → 坐标不变，只把旧固定缩放替换为连续值；验证同一批坐标迁移前后的视觉差异可接受。

## Migration Plan

1. 先实现配置迁移和统一舞区校验，使用当前 `config.json` 验证范围、缩放、亮度均符合预期。
2. 同时更新 Python 消息与前端类型，确保角色消息不再依赖 `band`。
3. 更新控制台与角色渲染，启动后确认所有旧角色仍显示且未重置位置。
4. 验证四向、斜向、无效指令、边界夹取和 100 人负载。
5. 部署前备份 `config.json`；若需回滚到旧版本，恢复备份并回滚前后端代码，避免新舞区配置被旧版本忽略。
