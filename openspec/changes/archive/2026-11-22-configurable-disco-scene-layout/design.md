# Design

## Context

当前 `disco.resources` 是固定对象，前端只按 `ceilingWall` 与其他槽位把资源分成背景和舞台两层；所有资源已有坐标与缩放字段，但控制台只编辑路径。活动带已由后端 `mid`、`near` 的矩形范围控制，配置更新只广播新配置，不会立即校正已有角色。相关行为见 `proposal.md` 和 `specs/`。

## Goals / Non-Goals

**Goals:**

- 保留固定远景墙和 DJ 台，同时把可扩展装饰拆成有序动态物品列表。
- 让固定资源和动态物品都使用世界坐标中的 X、Y、宽度和高度。
- 建立稳定层级：物品在观众后面，DJ 台在全部角色前面、前景柔光后面。
- 让 DJ 镜头使用当前 DJ 台位置。
- 活动带范围变化后立即恢复“所有角色都在合法范围内”的约束。

**Non-Goals:**

- 不实现中景与近景之间的穿梭。
- 不增加从前代码中移除的自动化测试体系。
- 不实现图片上传、在线裁切或图层内自由旋转。
- 不允许动态物品跨到观众、DJ 台或前景柔光之上。

## Decisions

### 1. 保留 `resources`，新增 `items` 数组

保留：

```text
disco.resources.ceilingWall
disco.resources.djBooth
```

新增：

```text
disco.items[]
```

每个固定资源或物品至少包含：

```json
{
  "id": "speaker-main",
  "path": "/disco/assets/scene/speaker.png",
  "x": 1200,
  "y": 560,
  "width": 320,
  "height": 480,
  "lock_aspect": true,
  "flip_x": false,
  "origin_x": 0.5,
  "origin_y": 0.5,
  "opacity": 1,
  "tint": "#ffffff"
}
```

固定资源的 `id` 由槽位决定，物品必须有唯一 `id`。宽度和高度使用世界像素；缺少宽高时，前端可以暂用纹理原始尺寸和旧 `scale_x/scale_y` 兼容旧配置，控制台保存时补齐实际宽高。

替代方案是把所有资源统一塞入动态数组，但这样会允许删除远景墙或 DJ 台，与“固定资源必须存在”的要求冲突。

### 2. 直接移除旧左右舞台

新的配置结构不再包含固定 `resources.leftStage` 和 `resources.rightStage`。旧字段不会转换为动态物品，也不会继续渲染；运营者需要按新物品列表重新添加所需装饰。此变更不提供旧舞台布局兼容，动态物品列表从当前配置声明的物品开始。

### 3. 宽高与比例锁在浏览器端处理

控制台直接编辑宽度和高度。锁定比例时，前端使用当前资源的显示宽高比同步另一项。新增物品或更换路径时，浏览器加载图片元数据以获得原始比例，并用默认最大边限制初始尺寸。

前端渲染使用明确的 `width` 和 `height`，不再依赖原图分辨率。旧配置缺少宽高时，使用纹理原始尺寸乘 `scale_x/scale_y` 作为兼容显示。

动态物品包含独立的 `flip_x` 布尔值，默认 `false`。启用时前端围绕物品自身中心进行水平镜像，不改变 X/Y、宽高、锚点或物品排序；固定远景墙和 DJ 台不参与该选项。

替代方案是只配置统一缩放倍率，但不同分辨率的音响、灯箱和摆件会产生不可预期的视觉尺寸。

### 4. 动态物品使用数组顺序作为层内顺序

前端在动态物品容器内设置 `zIndex = 数组索引`。后添加的物品追加到数组末尾，因此显示在所有较早物品前面；“上移”提高索引，“下移”降低索引。上移和下移只调整物品之间的顺序，不能越过固定层级边界。

替代方案是单独配置任意 `z` 值，但会允许物品越到角色前方，也与用户要求的操作方式不一致。

### 5. 固定层级使用独立 DJ 容器

世界层顺序：

```text
Base              -10
CeilingWall         0
DynamicItems       10
LightBehind        20
MidCharacters      30
NearCharacters     40
DjBooth            45
LightFront         50
Fixed UI          DOM
```

DJ 台从现有 `stageSet` 中拆出到独立容器，保证角色移动、换层或后续动态物品变化时都不会改变其层级。前景柔光仍可覆盖 DJ 台。

替代方案是把 DJ 台作为动态物品，但动态物品被限定在角色后方，无法满足 DJ 台高于角色的要求。

### 6. DJ 镜头读取布局坐标

`DJ 台脚本运镜` 的缩放、过渡和停留参数仍来自 `disco.camera.dj_shot`，目标中心改为 `disco.resources.djBooth.x/y`。若 DJ 台资源异常缺失，则回退到原镜头坐标并记录错误。

这样布局坐标只有一个来源，不需要用户在两个位置同步维护 DJ 台位置。

### 7. 活动带范围在保存前验证，保存后立即夹回

控制台为 `mid`、`near` 分别显示最小 X、最大 X、最小 Y、最大 Y。后端在保存配置前验证两个范围都形成非空矩形；无效补丁不写入 `config.json`，也不替换当前运行配置。

有效配置写入后，后端遍历活动角色：

- 角色仍在原 `band`。
- X/Y 夹取到该活动带的新矩形。
- 仅对发生变化的角色广播 `move`。
- 扩大范围时不主动移动角色。

该处理直接恢复服务端持有的位置约束，不依赖下一次移动事件。中景与近景穿梭仍不在本次范围。

### 8. 动态资源路径规范化和加载

控制台接受 `assets/...`、`scene/...` 或 `/disco/assets/...` 形式的输入。保存值统一为 `/disco/assets/...`。运行时仍从构建后的 `web/disco/assets/` 加载；开发目录中的新增资源必须通过现有构建流程复制后才能请求。

动态物品数量设置合理上限，避免无限列表造成加载和绘制压力。单个物品失败只记录该物品的错误，不影响固定资源和角色。

### 9. 自由运镜开关与静态镜头

`disco.camera.free_pan_enabled` 默认 `true`。镜头控制器新增静态模式；关闭自由运镜时记录并保持当前合法镜头状态，手动操作结束后的恢复目标和脚本镜头结束后的回退目标都改为该静态位置。

重新开启时以当前静态位置为起点恢复自由巡游，不瞬移回 `camera.start`。手动操作和脚本镜头不依赖该开关，仍可按原优先级执行。

## Risks / Trade-offs

- **DJ 台高于角色后会遮挡观众** → 遵循明确需求，并在配置界面提示层级的实际效果。
- **更换路径后锁定比例可能基于旧图** → 路径加载成功后立即用新图原始比例更新高度或宽度。
- **宽高被设置为零或非法数值** → 保存前限制为正数并回退到安全尺寸。
- **过多物品降低帧率** → 设置物品数量上限，缺图不阻塞其他层，并沿用现有低帧率降级。
- **无效活动带配置** → 在写盘前拒绝整个无效补丁，保留当前配置和角色位置。
