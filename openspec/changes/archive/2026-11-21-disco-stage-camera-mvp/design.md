# Design

## Context

现有服务在 `main.py` 中创建 aiohttp 应用，`App.on_event` 接收平台归一化事件后交给 `Pipeline`，`App.push` 将 JSON 广播给所有 `/ws` 客户端。`/ws` 当前返回 `hello`、历史消息和状态，但业务事件只保存面向人的 `desc`，不能直接驱动场景。见 [proposal.md](proposal.md) 和 `specs/` 中的行为约束。

当前项目没有前端构建工具链和自动化测试目录。`/live2d` 使用 `web/vendor/pixi.min.js` 的 PixiJS v7 全局运行时，并由 PyInstaller 整体收集 `web/`。Disco 需要独立构建，避免替换这个运行时。页面仍由同一个本机 aiohttp 服务提供，并继续使用现有端口和 `/ws`。

## Goals / Non-Goals

**Goals:**

- 在现有 Python 服务内增加一个有明确边界的 Disco 状态层，使角色上限、超时、位置边界和快照由服务端统一决定。
- 在同一 `/ws` 上增加结构化 Disco 消息，不改变现有 `hello`、`event`、`reply` 和其他消息的既有含义。
- 新增独立构建的 `/disco` 页面，使用分层世界、双模式镜头、预生成柔光和固定屏幕 UI。
- 让场景资源、观众活动带、柔光和镜头参数能够通过配置调整，而不需要修改渲染代码。
- 保持 `/live2d` 页面、PixiJS v7 依赖和模型接口不变。

**Non-Goals:**

- 不实现 3D、真实体积光、直线激光主视觉或 LED 大屏。
- 不实现前景栏杆、烟雾或其他实体遮挡物。
- 不实现完整 DJ 榜、礼物经济、皮肤文件上传/在线裁切、角色装扮系统和音乐节拍分析。
- 不把 Disco 状态持久化到数据库；程序关闭后角色状态清空。
- 不把 Disco 页面嵌入 `/live2d`，也不替换现有全局 PixiJS。

## Decisions

### 1. 在服务端增加内存态 Disco 管理器

新增 `disco.py`，由 `App` 持有一个 `DiscoManager`。它负责：

- 将原始直播事件转换为 Disco 角色和镜头动作。
- 维护以 `platform:uid` 为主键的活动角色表、位置、皮肤、最近互动时间和数量配额。
- 在角色创建、移动和超时销毁时生成结构化消息。
- 生成 `/ws` 连接快照，并提供配置热更新消息。
- 对文本长度、角色上限和用户去重做统一校验。

当平台没有稳定 UID 时，使用“平台 + 规范化名称”的会话级键，并记录降级原因。角色位置和活动带归属由服务端决定，前端只负责呈现，避免多个显示页面算出不同位置。

替代方案是让每个浏览器自行保存角色状态。该方案在 OBS 刷新时会丢失角色，也会让多个预览页面显示不一致，因此不采用。

Disco 管理器对象可以在程序启动时创建，但角色超时清理任务只在服务启动后存在。启动时如果 `disco.enabled` 为假，不创建清理任务；暂停时取消该任务、清空活动角色并广播停用状态。平台事件只在实际运行状态下复制并交给 Disco，暂停时保留原有 AI 流程。

### 2. 原始事件复制后双路分发

`App.on_event` 先向 Disco 管理器传入原始事件副本，再按原顺序调用现有 `Pipeline.on_event(ev)`：

```
platform event
      |
      v
App.on_event
  |             |
  v             v
Disco copy     Existing Pipeline
  |             |
  v             v
Disco events   AI / TTS / Live2D / Songs / Games
```

采用副本的原因是现有 Pipeline 会修改 `raw_name`、`name` 和固定回复标记。Disco 必须拿到未经修改的原始文本和用户身份；AI 链继续使用原有对象，避免改变其冷却、合并和回复行为。

如果 Disco 未启用，管理器不产生状态变化和广播；`Pipeline` 仍按现有逻辑运行。Disco 内部的配置错误或单条坏消息会记录日志并隔离，不能中断平台事件循环。

### 3. `/ws` 使用独立的 Disco 消息族

保留现有消息不变，新增以下消息：

```json
{"kind":"disco","action":"snapshot","seq":1,"enabled":true,"config":{},"characters":[]}
{"kind":"disco","action":"create","seq":2,"uid":"bilibili:123","name":"观众","skinId":"default","band":"mid","x":1200,"y":690}
{"kind":"disco","action":"move","seq":3,"uid":"bilibili:123","x":1240,"y":690,"direction":"left"}
{"kind":"disco","action":"say","seq":4,"uid":"bilibili:123","text":"晚上好","expiresAt":1760000000000}
{"kind":"disco","action":"change","seq":5,"uid":"bilibili:123","skinId":"skin-b"}
{"kind":"disco","action":"focus","seq":6,"uid":"bilibili:123","reason":"gift","priority":2,"ttlMs":5000}
{"kind":"disco","action":"shot","seq":7,"target":"dj","priority":3,"ttlMs":6000}
{"kind":"disco","action":"despawn","seq":8,"uid":"bilibili:123"}
{"kind":"disco","action":"config","seq":9,"config":{}}
```

`seq` 只在当前连接快照之后严格递增。页面收到新的 `snapshot` 时整体替换状态，忽略比快照更旧的增量。现有页面按 `kind` 忽略未知的 Disco 消息。

连接完成 `hello` 后，服务端立即发送一次 `action: "snapshot"`。这是独立消息而不是修改 `hello` 的既有结构，便于旧客户端继续工作。

### 4. 角色规则与活动带

配置中定义两个活动带。默认平面采用矩形边界，方便将移动目标和超时角色可靠地限制在区域内：

```text
mid  band: x=260..3580,  y=620..800,   baseScale=0.72..0.82
near band: x=140..3700,  y=790..1040,  baseScale=0.86..1.0
```

所有位置均指角色脚底锚点。`move` 动作按方向计算目标点，再通过 `clampToBand` 限制；无效活动带、非有限数值和负移动量按配置上限拒绝。角色实际缩放可在带内按脚底 `y` 线性插值，增强纵深感。

中景和近景分别放入可排序的观众容器。同一活动带内的 `zIndex = 脚底 y`，近景容器整体高于中景容器。角色名称和气泡跟随角色位置，但不参与“实体遮挡”判断。世界实体层不包含前景栏杆或烟雾。

替代方案是自由二维寻路。该场景没有可行走障碍物，自由寻路会引入无收益的碰撞计算，因此采用带边界和简单相对移动。

### 5. 分层渲染与配置清单

前端的世界层如下：

```
Viewport
  +-- CeilingWall
  +-- StageSet
  |     +-- LeftStage
  |     +-- DjBooth
  |     +-- RightStage
  +-- MidCrowd
  +-- NearCrowd
  +-- LightBehind
  +-- LightFront
Stage（固定屏幕）
  +-- UIOverlay
```

每个资源项包含 `slot`、`path`、`x`、`y`、`scale`、`origin`、`opacity` 和 `tint`。加载器先读取完整清单，再逐层加载并报告失败资源；一个层失败不会阻止其他层或 `/ws` 连接。资源始终使用本地 `/disco/assets/` 路径，不依赖 CDN。

默认不创建 `Foreground` 根节点，避免后续美术代码意外加入遮挡物。柔光使用单独的 `LightBehind` 与 `LightFront` 层，均不属于实体世界层。

### 6. 预生成柔光纹理

启动时用 Canvas 2D 渐变生成两种基础纹理：径向柔光核心和纵向渐变光雾。生成后可选择执行一次离屏模糊并缓存为纹理，运行时不对运动中的光源反复应用大范围 `BlurFilter`。

每个主光源由宽椭圆光雾和较亮的中央光核组成，默认 4 至 6 组，使用加色混合、低透明度和轻微横向漂移。背景洗墙光独立于观众区前景柔光。光源参数按配置实时重建轻量 sprite 或调整已有 sprite 的属性。

替代方案是每帧对 `Graphics` 执行高斯模糊。该方案容易造成高填充率和帧率下降，且运动光源边缘可能出现不稳定，因此只保留为一次性纹理生成手段。

### 7. 镜头控制器与优先级

镜头状态使用 `centerX`、`centerY` 和归一化缩放 `zoomFactor`。基础缩放根据画布尺寸计算，使逻辑画面始终展示 1920×1080 的世界范围；配置中的 `1.0–2.0` 表示相对于这个基础缩放的比例。

三种行为：

- `free-pan`: 使用三角波和缓动函数在安全范围内往返，默认单程 30 秒。
- `manual`: 用户拖拽或缩放时暂停自由运镜和脚本镜头，持续 8 秒无输入后恢复。
- `scripted`: 按目标中心、缩放、过渡时间、停留时间和优先级执行镜头。

优先级为“手动输入 > 高优先级脚本 > 低优先级脚本 > 自由运镜”。脚本镜头默认参数为角色特写 `1.6 / 1 秒过渡 / 3.5 秒停留`，DJ 台 `1.35 / 1 秒过渡 / 4 秒停留`。普通礼物镜头在 5 秒合并窗口内只执行一次；角色不存在或目标被销毁时取消脚本并恢复合法状态。

镜头位置每帧先通过 `getBoundsAtZoom` 计算允许的中心范围，再应用 `clamp`。窗口改变后重新计算基础缩放和边界，并立即应用一次限制，避免黑边。

### 8. 独立 Vite 项目与发布目录

新增独立 `disco-src/` 项目，包含自己的 `package.json`、锁文件、TypeScript 配置和 Vite 配置。依赖固定为 PixiJS v8、pixi-viewport v6、Vite 和测试工具；构建产物写入：

```text
web/disco/
  index.html
  assets/
    *.js
    *.css
    scene/
```

使用 `/disco/assets/` 作为资源基础路径。aiohttp 增加 `/disco` 页面路由和 `/disco/assets` 静态路由；由于 PyInstaller 已整体收集 `web/`，发布包不需要新增复杂的资源复制步骤。启动程序不会调用 Node、Vite 或包管理器。

替代方案是把 Disco 代码直接写进 `web/live2d.html`。两页所需的 PixiJS 主版本不同，直接复用会全局覆盖 `PIXI`，因此不采用。

### 9. 固定 UI 与错误边界

在线人数、FPS、当前镜头模式和调试开关使用 HTML/CSS 固定覆盖层，不放入镜头容器。默认样式指向 OBS 直播，调试信息隐藏，鼠标和操作提示不拦截页面以外的业务。

页面初始化分为图形上下文、配置加载、资源加载和 WebSocket 连接四个阶段。图形上下文失败时使用 DOM 错误层；资源失败时保留可用场景并显示缺图列表；连接失败时按指数退避重连并保留最后一次合法画面。

### 10. 角色皮肤数组与列表管理

`disco.skins` 的唯一合法结构是数组，每项至少包含唯一 `id` 和本地 `/disco/assets/role/` 路径。配置加载和合并时把旧版 `{"0": {...}, "1": {...}}` 索引对象迁移为数组，并始终把受保护的 `default` 项放在第一项，路径固定为 `/disco/assets/role/default.png`。

控制台从构建目录的 `/api/disco/skins` 读取可添加图片，以缩略图列表展示当前皮肤。非默认项支持新增和删除；默认项不显示删除操作，也不能通过输入框改路径。更换默认皮肤时由运营者直接替换 `disco-src/public/assets/role/default.png`，角色资源使用 `no-cache` 并在加载时禁用旧缓存，避免同名替换后仍显示旧图。

皮肤加载器按图片 Blob 解码 PNG、GIF、JPEG、WebP 和 SVG，而不是把所有响应都包装成 `image/svg+xml`。GIF 作为静态首帧显示，不额外引入动画控制器。

### 11. 服务生命周期与暂停渲染

控制台用单个“启动 / 暂停”按钮替换启用复选框。按钮文字根据后端实际清理任务状态显示：运行中显示“暂停”，未运行显示“启动”。配置接口同时返回 `_disco_running` / `disco_running`，避免仅凭配置值误判服务是否真的启动。

`/disco` 页面仍然先连接 `/ws` 以接收启停消息，但只有配置为启用时才创建 PixiJS 应用、加载场景和启动 ticker。运行中暂停时停止 ticker、清空角色并隐藏画布，保留页面与 WebSocket；再次启动时从服务端快照恢复。页面在停用状态下打开时只运行轻量 DOM 与 WebSocket，不初始化 WebGL。

暂停态保留已经创建的 WebGL 上下文和纹理内存，但不持续执行动画与绘制。彻底关闭浏览器源会释放前端全部内存；后端暂停不会留下周期性 Disco 任务。

### 12. 测试策略

- Python 侧使用 `unittest` 覆盖事件分流、用户去重、角色上限、超时、活动带夹取、快照和配置更新。
- Python 侧同时覆盖 `disco.skins` 对象到数组的迁移、默认皮肤路径保护、删除后默认项保留和角色资源目录筛选。
- Python 侧覆盖 Disco 清理任务的按需创建、暂停取消以及 API 返回真实运行状态。
- TypeScript 侧使用 Vitest 覆盖镜头边界、自由运镜方向、脚本优先级、快照替换和消息校验。
- 页面级测试覆盖 `/disco` 加载、`/ws` 快照、停用页面不创建场景、暂停后停止 ticker、按钮启停状态，并对 `/live2d` 进行静态引用回归检查。
- 性能验收使用 Chrome Performance，固定 100 个角色持续 30 秒，记录帧率和主线程长任务；低端条件手工验证降级分支。

## Risks / Trade-offs

- **双路分发遗漏或重复处理** → 在 `App.on_event` 只调用一次 Disco 和一次原有 Pipeline，并用副本隔离 Pipeline 的名称修改；为冷却、合并、暂停和未知事件增加回归用例。
- **服务器与浏览器角色状态不一致** → 位置、活动带和销毁决定全部由服务端负责，前端不在本地生成正式角色身份。
- **礼物洪峰导致镜头频繁漂移** → 镜头合并窗口、优先级和单活动脚本限制；低优先级请求可被丢弃，角色和弹幕仍保留。
- **大尺寸柔光造成填充率过高** → 预生成纹理、限制活动光源数量、透明度和分辨率，并保留自动降级。
- **背景拆图资源路径或尺寸不匹配** → 每个槽位独立加载并显示缺图提示；加载失败时其他层继续工作。
- **独立 v8 产物与 Live2D 的 v7 全局冲突** → 不共享全局运行时，两页使用各自打包产物；发布前检查 `/live2d` 的脚本引用和模型加载。
- **无 Node 环境无法运行** → 构建后的静态文件随 `web/` 一起进入 PyInstaller 包，并增加无开发环境启动验收。
- **内存状态在重启后丢失** → 该状态被明确限定为单次运行会话；重启后由后续平台事件重新建立角色。

## Migration Plan

1. 先合并后端配置默认值、Disco 管理器、消息协议和 `/disco` 路由，保持功能默认关闭。
2. 加入独立前端的开发构建，先用占位分层资源完成世界、观众带、柔光和镜头验收。
3. 替换正式背景、DJ 台和舞台切图，确认资源失败和配置更新行为。
4. 构建发布版静态产物，再执行 Python 打包和 `/live2d` 回归验证。
5. 回滚时关闭 `disco.enabled` 即可停止 Disco 状态广播；如果撤回全部功能，删除新页面、构建目录和路由，不改动旧数据库或 Live2D 文件。

配置加载沿用现有深合并机制，新增的 `disco` 字段在旧 `config.json` 中不存在时会自动补齐，因此不需要数据迁移。
