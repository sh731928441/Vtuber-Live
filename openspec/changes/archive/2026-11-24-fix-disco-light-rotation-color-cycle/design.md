# Design

## Context

参见 `proposal.md` 的 Why。当前实现通过修改灯光根节点的 `x` 平移整束光，并以每次随机挑选下一颜色的状态机播放颜色，因此不能形成以灯头为圆心的扇形扫动，也不能保证一轮完整遍历全部颜色。圆锥 Sprite 的顶部锚点已经位于根节点原点，可以天然作为旋转中心。

## Goals / Non-Goals

**Goals:**

- 以节点旋转替代水平平移，形成舞厅灯头固定、光束扫动的效果。
- 让全部光束共享数量和长度配置，同时保留彼此独立的旋转相位与速度。
- 每束光独立洗牌一次，并固定顺序无限循环渐变。
- 保持颜色池、顶部 Y、性能降级和控制台实时更新机制。

**Non-Goals:**

- 不旋转背景洗墙光或前景观众区柔光。
- 不把每束光的洗牌顺序持久化到 `config.json`；页面加载或颜色池变化时重新生成。
- 不新增三维透视、体积雾或真实光照计算。
- 不改变随机颜色开关现有的配置键和启用状态。

## Decisions

### 1. 灯头固定，使用根节点旋转

继续保持圆锥 Sprite 的 `anchor=(0.5, 0)`，根节点定位在 `top_y` 和各自的 `baseX`。摇摆时：

```text
root.x = baseX
root.y = top_y
root.rotation = sin(time * speed * phaseRate) * angle
```

`sway_angle` 以度存储，渲染前转换为弧度。正弦值使角度在 `-sway_angle` 与 `+sway_angle` 之间往返，每束光继续使用不同相位和速度倍率。关闭摇摆时角度立即归零，不再修改根节点 X。

相比旋转 Sprite 本身，旋转根容器可以确保整个光束共享同一个顶点，避免覆盖图片锚点或额外偏移。

### 2. 光源数量和统一长度

光源数量上下限改为 `3–10`，默认 `5`。数量变化时重建光束节点，并重新分配均匀的 `baseX`。

新增 `beam_length`，默认 `1010px`，控制台范围 `400–1600px`。所有光束的 Sprite 高度使用同一值，根节点不受长度影响，因此旋转中心始终固定在顶部。长度变化不需要重建纹理，只更新现有 Sprite。

### 3. 每束光固定洗牌袋

为每个光源节点保存独立颜色顺序：

```text
colorOrder: RgbColor[]
colorSequenceVersion: string
```

节点创建或颜色池签名变化时，使用 Fisher-Yates 对该节点的颜色池副本进行洗牌，之后不再改变顺序。颜色循环完全由连续时间计算：

```text
segmentIndex = floor(elapsed / intervalSeconds)
from = colorOrder[segmentIndex % length]
to = colorOrder[(segmentIndex + 1) % length]
progress = (elapsed % intervalSeconds) / intervalSeconds
color = lerp(from, to, smoothstep(progress))
```

因此从第一色到第二色、第二色到第三色直至末色回到首色都连续渐变，没有停留。单色池直接输出该颜色。颜色池变化或光源重建时生成新顺序；完成循环或开关变色时复用已有固定顺序，不重新洗牌。

背景洗墙光和前景柔光不参与该洗牌袋，继续使用各自的独立配置颜色与透明度。

### 4. 配置与控制台

新增配置：

```text
sway_angle            0–90°，默认 45
beam_length           400–1600，默认 1010
color_interval_seconds 0.5–5.0，默认 2.0
```

扩大：

```text
count                 3–10
sway_speed            0.2–5.0
```

控制台将“左右摇摆”保留为开关，将“摇摆幅度”替换为“旋转角度”，新增“光束长度”和“每段渐变秒数”；“随机变色”文案改为“循环变色”。继续复用现有 `/api/config` 保存和无刷新广播。

### 5. 兼容旧配置

`drift_x` 和 `drift_y` 继续允许存在于旧配置中，但不再决定摇摆位置。缺少新字段时服务端默认配置和前端 fallback 提供安全值。`random_colors` 键继续使用，但语义改为固定洗牌循环。

## Risks / Trade-offs

- `90°` 最大角度和较长光束可能让光柱部分转出画布 → 保留透明的纹理边缘和场景裁切，不限制用户的视觉配置选择。
- 每束光独立洗牌可能让首屏颜色分布不均 → 这是预期效果；同一周期内不会重复或漏掉颜色。
- 10 束光增加每帧颜色计算 → 每帧最多计算 10 次颜色插值，成本仍然很低；低性能模式继续隐藏部分光束。
- 调整颜色池会重启洗牌顺序 → 颜色池属于静态结构变化，重建可避免旧顺序引用失效颜色。
- 旧 `drift_x` 与新的 `sway_angle` 并存可能造成误解 → 控制台只展示旋转角度，旧字段仅保留配置兼容。

## Migration Plan

1. 增加服务端和前端默认字段并扩大数量、速度限制。
2. 将水平平移更新替换为根节点旋转。
3. 将逐次随机选色改为每束光固定洗牌袋和连续时间采样。
4. 更新控制台控件与文案，重新构建 `web/disco`。
5. 若需回滚，可恢复原 `drift_x` 平移动画和逐次随机颜色状态；新增配置字段可安全保留。
