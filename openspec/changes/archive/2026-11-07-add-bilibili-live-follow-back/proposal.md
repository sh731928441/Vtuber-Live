# 提案

## 为什么

当前程序能实时识别 B 站直播间里的关注事件，但只能对关注者进行语音感谢；主播仍需逐个进入观众主页回关，直播中操作频繁且容易遗漏。希望使用当前扫码或手动 Cookie 登录的 B 站账号，在检测到新的普通关注或特别关注后自动回关。

## 变更内容

- 保留 `INTERACT_WORD_V2` 的原始互动类型，使普通关注、特别关注和互粉可以被分别处理。
- 新增 B 站直播间自动回关服务：普通关注和特别关注触发回关，互粉跳过，避免重复修改关注关系。
- 使用当前 `bili_cookie` 登录态调用 B 站关注接口，要求 `SESSDATA` 与 `bili_jct` 同时存在。
- 将回关与现有 AI 语音队列解耦，采用独立、串行、带随机延迟和 UID 去重的任务队列。
- 增加默认关闭的“被关注时自动回关”配置与界面开关，并展示登录失效、成功、跳过和风控失败等状态。
- 默认跳过 UID 无效、自己关注自己以及命中现有忽略名单的用户。

## 能力

### 新增能力

- `bilibili-live-follow-back`: 基于当前 B 站登录账号，在直播间收到普通关注或特别关注后安全地自动回关，并向用户反馈处理结果。

### 修改能力

无。项目当前没有既有的 OpenSpec 能力。

## 影响

- 修改 `bili.py`：保留互动类型并接入独立回关服务。
- 修改 `main.py`：在原始事件入口分流回关任务，管理配置与登录态生命周期。
- 修改 `config.py` 和 `web/index.html`：增加默认关闭的自动回关配置、界面开关和状态提示。
- 使用网页侧 `POST https://api.bilibili.com/x/relation/modify`，参数包含 `fid`、`act=1`、`re_src=11` 和 `csrf`；`act=5` 表示拉黑，禁止用于本功能。
- 不改变现有 AI 回复、关注感谢、事件合并、冷却和优先级行为。
- 该接口属于 B 站网页非公开 API，存在变更、频率限制和账号风控风险。
