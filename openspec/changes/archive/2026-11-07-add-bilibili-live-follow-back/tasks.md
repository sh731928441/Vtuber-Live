- [x] 1.1 在 `config.DEFAULTS` 中加入 `bili_follow_back.enabled: false`；验证缺少该键的配置文件仍能正常加载，并报告功能已关闭。
- [x] 1.2 使用现有 `data-k` 配置绑定，在 B 站账号卡片中加入“被关注时自动回关”复选框；验证它可以正常加载和保存，且不会暴露 `bili_cookie`。
- [x] 1.3 关闭功能时立即清空等待中的回关任务；通过现有 `/api/config` 路由验证复选框状态能够保存，并验证清空行为生效。

## 2. 捕获原始关注事件

- [x] 2.1 扩展 B 站消息处理器，增加独立的原始关注回调，并在 `msg_type` 为 2、4 或 5 时调用，同时保持现有 `emit` 映射不变；验证普通关注和互粉仍会发出原有的 `follow` 事件，特别关注不会新增语音事件。
- [x] 2.2 将原始关注回调传入 `BiliLive`，且不阻塞 WebSocket 接收循环；验证入队操作不会在 `_on_interact_word_v2` 中执行网络 I/O 或等待操作。
- [x] 2.3 在 `App` 中接入原始关注回调，使符合条件的事件在进入 `Pipeline.on_event` 前到达协调器；验证多个快速到达的关注事件都能保留各自的 UID。

## 3. 回关协调器

- [x] 3.1 实现 Cookie 可用性检查，要求已打开的会话包含 `SESSDATA` 和 `bili_jct`，且不得记录它们的值；验证缺少键和键完整两种测试。
- [x] 3.2 实现关注关系适配器，以表单 POST 提交 `fid`、`act=1`、`re_src=11`、`csrf`、User-Agent 和直播间 Referer；验证模拟成功响应会报告成功、非零状态码会报告平台失败，并明确断言 `act` 等于 `1` 且绝不等于表示拉黑的 `5`。
- [x] 3.3 实现异步队列以及启动、入队、清空和停止等生命周期方法；验证关闭应用和停用功能都会取消等待任务。
- [x] 3.4 实现单次运行内的 UID 去重和互粉跟踪；验证重复的普通关注、特别关注和互粉事件对每个 UID 最多产生一次符合处理条件的决策。
- [x] 3.5 实现无效 UID、当前登录 UID 以及现有忽略名单名称或 UID 的排除规则；验证每种排除都会记录跳过原因，且不调用适配器。
- [x] 3.6 实现串行处理，在请求之间加入 3 至 8 秒随机延迟，并且只对网络错误或 HTTP 5xx 重试一次；验证认证错误、CSRF 错误、HTTP 412 和接口语义错误不会重试。
- [x] 3.7 通过现有本地日志输出成功、互粉、跳过、认证失败、平台拒绝和传输失败结果，不调用 `Pipeline`，也不创建 AI 语音任务；在协调器测试中验证每条路径。
