# Design

## Context

控制台当前通过 `POST /api/disco/bubble` 调用 `DiscoManager.send_bubble`，仅能更新目标角色气泡。真实弹幕则在 `DiscoManager._command` / `on_event` 中具有移动、换肤、销毁和创建行为。相关行为见 `proposal.md` 和 `specs/disco-event-stream/spec.md`。

## Goals / Non-Goals

**Goals:**

- 用统一的目标 UID 模拟弹幕入口替代气泡专用控件。
- 复用现有目标角色指令语义和解析器。
- 保持模拟弹幕与真实直播事件、AI、TTS、Pipeline 完全隔离。
- 正确处理创建角色静默 no-op 和全局指令拒绝。

**Non-Goals:**

- 不增加新的角色指令语法。
- 不把模拟弹幕写入控制台直播间消息或真实事件历史。
- 不通过目标 UID 控件执行 DJ 台镜头等全局操作。
- 不改变 NPC 添加/删除或皮肤基础缩放功能。

## Decisions

### 1. 新接口替代气泡接口

控制台改为调用：

```text
POST /api/disco/danmaku
{ uid, text }
```

该接口只接受一个现有目标角色和一段弹幕文本。旧的 `/api/disco/bubble` 和气泡专用控件被移除，避免两个入口产生不同语义。普通文本内部仍复用现有 `_say`，因此气泡截断、TTL 和广播格式保持一致。

### 2. 先解析目标，再解析指令

目标解析顺序与现有气泡入口一致：

1. 精确匹配内部 UID，例如 `npc:runtime:3` 或 `viewer:bilibili:123`。
2. 未命中时，把输入解释为当前直播平台原始 UID，并查找 `viewer:<platform>:<uid>`。
3. 仍未找到时返回 HTTP 404 语义和“角色不存在”，不创建角色。

目标存在后，普通文本直接走气泡；以当前 `command_prefix` 开头的文本进入目标角色指令分派。

### 3. 提取目标角色指令执行器

从现有 `_command` 中提取只依赖目标角色的指令执行逻辑，供真实事件和模拟弹幕共用：

```text
移动 / 移动到 -> _parse_move_command + clamp_to_dance_floor
切换角色 [id] -> _change_skin_for_character
创建角色 -> 目标已存在时 no-op
销毁角色 -> 删除目标 character + despawn 广播
镜头 ... -> 标记为全局指令
未知指令 -> 解析错误
```

真实事件仍负责首次创建角色和身份去重；模拟入口不负责创建，因此缺少目标时始终报错。

### 4. 创建角色静默 no-op

模拟弹幕识别到 `创建角色` 后，在目标已存在的前提下直接返回 `{ ok: true, silent: true }`。该路径不修改 `last_seen`、不递增序列号、不广播消息、不刷新前端状态，控制台也不显示 toast。

这与普通成功消息不同；其他成功指令和普通文本会显示“模拟弹幕已发送”，并广播必要状态。

### 5. 全局指令拒绝

DJ 台镜头等指令需要操作整个场景，不属于目标 UID 的角色状态。模拟入口识别到全局指令时返回可读错误：

```text
该指令为全局指令，请使用镜头控件
```

错误不产生任何场景副作用。未知目标角色指令同样返回错误，不落回普通气泡。

### 6. 与真实直播事件管线隔离

路由只调用 `DiscoManager` 的模拟弹幕方法，不调用 `App.on_event`、`Pipeline.on_event`、AI 或 TTS。普通模拟弹幕和有效目标角色指令会刷新目标角色活动时间；创建 no-op 不刷新。所有 Disco 状态变化仍通过现有 `_publish` WebSocket 广播。

### 7. 气泡使用绝对到期时间

服务端同时发布 `ttlMs` 和基于系统时间的绝对 `expiresAt`，快照中的未过期气泡也携带相同的绝对到期时间。前端状态存储以 `expiresAt` 判断有效性，并在处理移动、切肤等非 `say` 更新前丢弃已过期气泡。

角色视图只在收到新的气泡内容或新的到期时间时更新气泡节点。移动等更新可以携带仍然有效的气泡状态，但不得重新调用展示逻辑或按 `ttlMs` 重置计时；本地渲染循环发现当前时间达到 `expiresAt` 后立即隐藏气泡。这样可避免过期气泡因角色位置更新而复现，并让气泡在显示期间保持原来的停留时长。

## Risks / Trade-offs

- **真实事件和模拟事件的指令分派逐渐分叉** → 把移动、换肤、销毁等目标角色操作提取成共享执行器。
- **全局指令看起来像目标角色指令** → 显式维护全局指令列表，并返回引导性错误。
- **`创建角色` 在模拟入口没有实际效果** → 按已确认要求静默返回，不提示也不广播。
- **删除目标角色后控制台仍保留输入** → 保持输入内容，仅显示成功提示；后续操作会按“角色不存在”处理。
- **误以为模拟弹幕进入 AI 回复链** → 接口不调用 `App.on_event` / Pipeline，并在控制台提示中明确隔离。
- **浏览器与服务端时钟不同** → 仍以服务端绝对时间控制气泡总寿命；前后端时钟偏差只影响首帧剩余时长，不会让旧气泡被移动更新反复重置。

## Migration Plan

1. 增加模拟弹幕管理方法和 `/api/disco/danmaku` 路由。
2. 控制台字段、按钮和请求切换到新接口。
3. 抽取共享目标角色指令执行器，保持真实弹幕命令行为不变。
4. 验证普通气泡、移动、换肤、销毁、创建 no-op、全局指令和不存在 UID。
5. 移除旧气泡专用路由和 UI；代码回滚时恢复旧接口即可，不涉及持久化配置迁移。
