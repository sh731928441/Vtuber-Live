# Design

## Context

参见 `proposal.md` 的 Why。当前角色位置使用固定比例指数插值，灯光每帧把不同相位的余弦值叠加到每束光的 Y 坐标，导致高度不一致。锥形纹理顶部还存在较大的透明渐隐区，因此即使容器 Y 为 `0`，视觉亮部也会从更下方开始。场景目前通过分散的固定 `zIndex` 决定层级，DJ 台高于舞区角色。

## Goals / Non-Goals

**Goals:**

- 以可验证的匀速直线位移替换当前衰减插值。
- 将蹦跶限制在角色图片的局部视觉变换中，保持脚底坐标和层级稳定。
- 建立统一的灯光顶部坐标、独立 X 轴摇摆和颜色渐变。
- 集中定义场景层级，并为未来独立 DJ 角色预留明确位置。
- 保留当前工作区已有的角色名称字号和临时 Y 调整，避免覆盖用户改动。

**Non-Goals:**

- 不新增独立 DJ 角色的资源、身份、指令或控制台管理功能。
- 不改变 `/disco` 移动指令语法、服务端目标坐标或 WebSocket 协议。
- 不新增颜色拾取器；颜色继续来自现有“颜色（每行一个）”文本域。
- 不调整角色名称字号或气泡字号。

## Decisions

### 1. 匀速直线移动与局部蹦跶

角色容器保存当前坐标、目标坐标和本段移动速度。每帧计算剩余距离并按 `速度 × deltaSeconds` 沿单位方向向量前进；剩余距离不足一步时直接吸附到目标。默认速度取约 `120 px/s`，保证 `20–30 px` 的常规指令仍有可辨识的动作，同时不会出现明显拖尾。

蹦跶只作用于图片 Sprite 的局部 `x/y/rotation`：

- 移动时叠加小幅左右偏移和上下跳跃，使用固定的移动专属周期与相位。
- 角色容器仍严格沿直线移动，名称和气泡不参与跳动。
- 到达目标后清除移动状态，让图片局部变换快速回归零点。
- 静止时保留现有缓慢待机动画，但降低它与移动蹦跶之间的视觉混淆。

不采用“整个轨迹蛇形”的方案，因为那会使实际路径偏离目标直线，也会破坏斜向移动和边界表现。

### 2. 统一灯光顶部与视觉顶格

新增 `disco.lights.top_y`，默认 `0`。所有光束根节点的 Y 直接使用 `top_y`，删除按光源索引和相位计算的 Y 轴余弦漂移。`drift_y` 为兼容旧配置继续保留，但不再改变光束高度；旧配置文件无需人工删除该字段。

为让视觉上沿真正顶格，同时维持纹理边缘 Alpha 为 `0`：

- 保持光束 Sprite 顶部锚点。
- 将纹理最上方的完全透明区和顶点渐隐区缩短到只有少量像素。
- `top_y=0` 时允许第一行完全透明，但数个像素内出现可见光锥，不能再形成约几十像素的空白带。

背景洗墙光也以 `top_y` 作为上边缘计算位置。前景柔光继续相对灯组顶部保持原有垂直偏移，因此修改 `top_y` 时整组灯光一起平移，但不改变观众区的相对构成。

### 3. 独立摇摆与渐变颜色

灯光配置新增：

```text
top_y          number
sway_enabled   boolean
sway_speed     number
random_colors  boolean
```

现有 `drift_x` 继续作为左右摇摆振幅，控制台标签改为“摇摆幅度”。`sway_speed` 默认 `1.0`，合理范围约为 `0.2–3.0`。

开启摇摆时，每个光源节点使用不同的基础频率倍率和相位，使运动既连续又不同步；关闭时 `X` 保持固定基础坐标。质量和性能降级仍可减弱或减少灯效，但不能重新引入 Y 高度差。

随机变色在 4–6 个光源之间独立运行：

- 每个光源从当前颜色平滑插值到从 `lights.colors` 中随机选中的下一颜色。
- 单次渐变使用约 1.5–2.5 秒，完成后停留一段时间再选择下一目标。
- 当前目标与下一目标按同一相位插值，避免中途重新开始造成跳色。
- 颜色数组不足两个时保持第一个有效颜色。
- 背景和前景柔光共用同一颜色方案，但拥有独立的目标颜色与时间相位。

### 4. 集中管理场景层级

把分散的数字改为具名层级常量，并在场景初始化时创建独立 DJ 角色容器以便未来复用。目标顺序：

```text
前景柔光
舞区角色
固定 DJ 台
独立 DJ 角色
背景柔光
动态物品
固定远景墙
世界底色
```

舞区角色内部仍按脚底 Y 排序。独立 DJ 角色容器当前为空，不改变现有画面；未来加入 DJ 角色资源时无需再次调整其他图层。

### 5. 配置兼容与控制台

服务端默认配置和前端 fallback 配置增加上述字段。旧配置缺少字段时按默认值运行；`top_y` 只接受有限数字，`sway_speed` 被限制在安全范围。控制台在现有“柔光”卡片增加：

- 顶部 Y：数字输入，默认 `0`
- 是否左右摇摆：复选框，默认关闭
- 摇摆速度：范围控件，默认 `1.0`
- 是否随机变色：复选框，默认关闭

配置继续使用现有 `/api/config` 保存和无刷新广播流程。

## Risks / Trade-offs

- 匀速速度过快会让短距离蹦跶不易辨认 → 使用居中速度并按距离决定安全的最小移动持续时间，同时保持单次移动内速度恒定。
- 左右摇摆振幅过大可能暴露光源底部画布边界 → 继续使用质量降级和边缘透明的现有约束，并把振幅限制在安全范围。
- 每盏灯独立变色会增加状态和颜色计算 → 光源最多 6 个，颜色插值成本很低，且降级模式可减少活动光源。
- 旧 `background_wash.y` 与新 `top_y` 同时存在可能造成理解冲突 → `top_y` 成为顶部位置唯一来源，旧字段保留解析但不参与顶部对齐。
- 当前工作区已有用户手动修改的灯光 Y 和角色名称字号 → 实施时先读取工作区差异，只替换需要重构的移动/灯光逻辑，不覆盖无关值。
- 舞区角色改为高于 DJ 台后，部分角色气泡可能覆盖 DJ 台 → 这是预期层级结果，同时仍由前景柔光在上方做柔和融合。

## Migration Plan

1. 为旧配置补齐灯光新字段默认值，保持现有颜色和振幅设置。
2. 更新控制台和前端配置类型，确认旧页面收到空值时可回退。
3. 替换角色移动和灯光动画，再进行层级常量整理。
4. 保持当前名称字号与无关手动改动，重新构建 `web/disco`。
5. 若需回滚，恢复旧灯光 Y/颜色动画和角色插值即可；新增配置字段可安全留在配置中。
